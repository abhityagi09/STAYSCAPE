# Environment configuration

The API validates its whole environment at start-up (`apps/api/src/config/env.ts`) and refuses
to start on any invalid or unsafe value — for example development secrets, the sandbox payment
gateway or insecure cookies when `NODE_ENV=production` and `DEPLOYMENT_ENV=production`. Error
messages name the variable but never echo its value.

| File                      | Purpose                                                                                            |
| ------------------------- | -------------------------------------------------------------------------------------------------- |
| `.env.example`            | Every variable with safe local defaults. Copy to `.env` for development.                           |
| `.env.production.example` | Production template (no values; secrets come from the secret store).                               |
| `.env.staging`            | Generated by `node scripts/make-staging-env.mjs` for a self-contained staging stack (git-ignored). |

## Environments

|                                 | `local` (default)                                 | `staging`                                     | `production`                                  |
| ------------------------------- | ------------------------------------------------- | --------------------------------------------- | --------------------------------------------- |
| `NODE_ENV`                      | development                                       | production                                    | production                                    |
| Payment gateway                 | labelled sandbox or Razorpay **test** keys        | labelled sandbox (or Razorpay test keys)      | Razorpay **live** keys only                   |
| Secrets                         | `dev-only-…` defaults allowed                     | generated, never `dev-only-…`                 | from the secret manager, never `dev-only-…`   |
| Cookies                         | `COOKIE_SECURE=false` allowed on http://localhost | Secure                                        | Secure, behind TLS                            |
| Seed data / dev admin bootstrap | allowed (local database only)                     | allowed (the stack's own local database only) | **refused**; use `bootstrap-first-admin` once |
| Databases                       | Docker Compose                                    | private containers (`--profile self-hosted`)  | managed MongoDB (Atlas replica set) and Redis |

## Secrets

Values marked _secret_ below must come from the platform's secret store (GitHub environment
secrets, AWS Secrets Manager, Doppler, …) and are injected as environment variables at deploy
time. They are never committed: `.gitleaks.toml` + the CI secret scan enforce this.

Secret variables: `JWT_ACCESS_SECRET`, `DATA_ENCRYPTION_KEY`, `QUOTE_SIGNING_SECRET`,
`SANDBOX_PAYMENT_SECRET`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`, `SMTP_PASSWORD`,
`S3_SECRET_ACCESS_KEY`, `ANTHROPIC_API_KEY`, `METRICS_TOKEN`, `BACKUP_PASSPHRASE`.

Generate a strong value with:

```sh
node -e "console.log(require('crypto').randomBytes(36).toString('base64url'))"
```

**Rotation** (docs/security.md has the full procedure): `JWT_ACCESS_SECRET` rotation signs
everyone out within one access-token lifetime (refresh sessions stay valid); `QUOTE_SIGNING_SECRET`
rotation invalidates outstanding quotes (guests re-quote transparently); `DATA_ENCRYPTION_KEY`
encrypts partner settlement account numbers and **must not be rotated without the re-encryption
job** described in docs/security.md; `BACKUP_PASSPHRASE` must stay available for as long as backups
encrypted with it are retained.

## Web (Vite) build variables

Set at **build** time for `apps/web` (they are public — never put secrets in them):

| Variable               | Default           | Purpose                                                   |
| ---------------------- | ----------------- | --------------------------------------------------------- |
| `VITE_API_BASE_URL`    | `/api/v1`         | API origin/path; same-origin through nginx in production. |
| `VITE_MAP_STYLE_URL`   | OpenFreeMap style | MapLibre style URL (OpenFreeMap needs no key).            |
| `VITE_MAP_ATTRIBUTION` | OpenFreeMap / OSM | Attribution shown on the map.                             |

## Infrastructure variables (docker-compose.prod.yml)

| Variable                                                                         | Purpose                                                                         |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `PUBLIC_URL`                                                                     | Public origin (sets `API_PUBLIC_URL`, `WEB_APP_URL` and `CORS_ORIGINS`).        |
| `WEB_BIND`                                                                       | Interface and port the web container binds to (the TLS load balancer's target). |
| `REGISTRY`, `IMAGE_TAG`                                                          | Image repository and immutable tag (`sha-<commit>`) to run.                     |
| `STACK_NAME`                                                                     | Compose project suffix (`prod`, `staging`).                                     |
| `BACKUP_MONGO_URI`, `BACKUP_PASSPHRASE`, `BACKUP_RETENTION_DAYS`, `BACKUP_OPLOG` | Backups (docs/backup-recovery.md).                                              |
